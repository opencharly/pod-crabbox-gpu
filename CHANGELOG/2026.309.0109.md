# 2026.309.0109 — feat(image): add the virtual-GPU lease image pod-crabbox-gpu

## Summary

Adds `pod-crabbox-gpu`: the virtual-GPU lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the base lease contract (`opencharly/pod-crabbox`, pinned) plus the Venus Vulkan ICD, the software fallback ICD, `vulkan-tools` and mesa for the krun render path.

- **`charly.yml`** — the image: `base: ghcr.io/opencharly/pod-crabbox:2026.307.1828` (pinned OCI base), `user: root` (the base's `sshd -D` is PID 1) with the login user left at the base's `crabbox`/uid 1000, and `distro: [cachyos, arch]` + `build: [pac]` declared explicitly because an external OCI base does not inherit the CachyOS chain.
- **`candy/gpu-vulkan/charly.yml`** — the variant layer: `mesa`, `vulkan-icd-loader`, `vulkan-virtio` (Arch's Venus ICD), `vulkan-swrast` (CPU fallback) and `vulkan-tools` from the Arch repo package set, plus the base's SSH port (`2222`) restated because an OCI base does not carry its candy chain's port label across the boundary.
- **Seven deterministic `check:` steps** — the Venus ICD file `/usr/share/vulkan/icd.d/virtio_icd.json` exists; `pacman -Q vulkan-swrast`; `/usr/bin/vulkaninfo` is executable; `pacman -Q vulkan-icd-loader mesa`; the inherited lease binaries (`sshd`, `bootstrap.sh`, `ready`) exist; uid 1000 is `crabbox`; `/etc/ssh/sshd_config.d/99-crabbox.conf` names `Port 2222` and `sshd -t` parses it.
- **`.github/workflows/image.yml`** — the thin caller of the org reusable: `pull_request` / `workflow_dispatch` build only (the reusable derives a `ci-<sha>` tag and publishes nothing), and a successful `tag-on-merge` completion publishes the newest `v*` git tag as the image tag.
- **`README.md`, `AGENTS.md`, `CHANGELOG/.gitkeep`, `.gitignore`** — repo overview, repo guidance, the history directory, and generated-file ignores.

The branch carries a second commit, `fix(gpu): point the amdgpu-virtio note at the document that carries it`: the image description explained that the amdgpu-virtio mesa variant is not claimed and pointed at "the repo's README", but the rationale lives in `AGENTS.md`; the pointer now names that document. No code or package changes follow from it — the image is otherwise identical.

The image deliberately does NOT claim DRM native context: no Arch/CachyOS package carries `amdgpu-virtio` (see `## Filed issues`), so the supported Vulkan paths are the Venus ICD and the software fallback.
